Automation schedule

Every 5 min activity-watcher.py Python-first new-activity check (no LLM unless something new); on a new activity triggers Claude analysis, stubs session-log.json, and sends a Telegram coaching note with inline keyboard for RPE, nutrition, and pain capture
Continuous bot.py Two-way Telegram bot; routes messages to Claude or fast-path handlers; processes inline keyboard callbacks (RPE, nutrition, pain scores, FTP/CSS/LTHR updates); writes a poll-loop heartbeat
Every 5 min bot-watchdog.py Liveness guard — restarts the bot service if its heartbeat goes stale (catches a wedged poll loop)
Every 30 min · 06–09 morning-checkin.py Fetches HRV, sleep, and wellness from Intervals.icu; sends personalised daily readiness note and today's session preview
Daily 05:00 daily-prescription.py Daily session prescription for each active athlete — confirms or adjusts today's prescribed session against readiness and plan state
Daily 05:30 watchdog.py Daily watchdog — fires a Telegram alert only if a trigger trips (overreach, missed sessions, etc.); silent otherwise
Daily 06:20 refresh-site-data.py Fetches live training metrics from Intervals.icu; writes the full private training-data.json and an allow-list sanitised public variant (via lib/public_sanitise.py)
Daily 06:25 plan_audit.py Layer 4 self-check — asserts STRUCTURE/FUELLING/LONG_RIDE/WEEKLY_LOAD/RULES invariants against each athlete's live Intervals.icu calendar; read-only, hard-fail logs to ops-alerts.log (no Telegram)
Every 2h · 07–22 (:40) session-sync.py Reads recent chat history and extracts any new coaching rules or preferences the athlete has stated, syncing them into the rule surface
Hourly (:09) refresh-public-data.py Extracts public-safe fields (fitness trend, race countdown) from training-data.json; writes public/site-data.json — an allow-list sanitised copy enforced by lib/public_sanitise.SITE_DATA_SPEC. Does not push itself; cc-gitpull.sh commits and pushes it to GitHub Pages within 30 min
Every 30 min (:05, :35) cc-gitpull.sh Auto-commits and pulls/merges/pushes the public diamondpeak-site repo — the actual publish step for every public JSON file above; logs and raises a loud-failure alert on any fetch/merge/push error
Daily 20:30 night-before-brief.py Sends each active athlete a brief on tomorrow's prescribed session
Daily 21:00 evening-checkin.py The one evening question — as of 28 Jul 2026 this replaced the old capture-reminder cron (20:10) and absorbed its job (chasing an unlogged key session up to 36h old) into this single 21:00 ask, alongside its existing post-session-notes and tomorrow's-session reminder
Daily 21:30 ops-digest.py Evening ops digest — reads the day's run-status log and reports failures or anomalies across all cron jobs
Sunday 18:00 weekly-plan.sh Two-stage weekly plan engine (stage1-plan.py); replaced the old Sunday plan generator. Gated — only pushes a week that passes the protocol audit, so a non-clean week leaves the athlete's existing plan untouched
Sunday 20:00 weekly-summary.py Fetches week's training data directly from Intervals.icu; generates compliance card with TSS, fitness change, sleep, fuelling; evaluates 8 decision triggers (recovery, overreach, phase transitions, injury, nutrition, HRV); sends to Telegram
Daily 23:20 sync-private-repo.sh Mirrors live athlete data (excluding secrets) into the private dpc_private repo, giving it real version history
Daily 23:50 backup-config.sh Encrypts athletes.json and commits the ciphertext to the private repo as a backup
Daily 00:00 bug-fixer.py --fix Nightly bug-fixer — two-stage pipeline reviewing the feedback/bug log against the whole rule surface and applying fixes
On demand generate-blueprint.py Generates the season training blueprint — phase structure, TSS ceilings, test schedule — and pushes test events to Intervals.icu calendar
On demand generate-race-plan.py On-demand full race-day plan document — per-leg pacing bands, HR ceilings, and nutrition — across all tri distances; triggered via Telegram

This table lists the ClaudeCoach entries in the VM crontab only. A separate, unrelated cron entry (Monday 09:00, expense-bot's backup_staleness_alert.sh) also runs on this box and is out of scope here.

Athlete data & privacy

Athlete data (session logs, health metrics, training history) is stored on the VM and mirrored to a private repository. The athlete data files the refresh scripts produce are gitignored and are no longer pushed to the public repository. As a result, the public athlete and coach dashboards currently have no live data source.

Onboarding

New athletes are invited by the admin via /invite <chat_id>. The bot walks them through a multi-step Telegram questionnaire: name, target race, Intervals.icu credentials — then immediately fetches FTP, thresholds, and fitness history from ICU and asks only for the gaps. The admin approves with /approve <slug>, which scaffolds the athlete folder, generates a personalised system prompt, and activates coaching.
